## Key Decisions

1. Port the 7 Node sites verbatim, in Node's order — see Research table (R1-R9); do not re-derive semantics
2. `mark_steered` runs in the same actor tick as the frame write (Node: "same synchronous section", `dist/acp-agent.js:1166-1173`) — the session actor is single-threaded so calling it right before `control.send_user` satisfies this
3. Outcome snapshot = existing `DeferredSettle {stop_reason, usage}` (`turn.rs:165-169`); reuse it for `steered_settle` — later results OVERWRITE (last result and its usage win, `dist:1562-1565`)
4. Steered results owe NO trailing idle (one idle covers interrupted + steered cycles, `dist:2618-2625`); the steer idle lane then pays for them by settling
5. Owed-idle branch stays BEFORE the steer idle lane (`dist:2108-2118` comment) — preserves the lagging-idle debt invariant
6. Orphan seeding on cancel uses ONLY the legacy count lane (`pending_orphan_results += 1` per pending steered echo); the `msg_lifecycle_v1` map (`trackOrphanCommand` `dist:3434-3442`) is out of scope
7. No new `TurnEvent` variants: settlement/activation events are unchanged, so `session.rs::handle_events` needs no change
8. Recorder gets a gated steer step (`after_updates: n`) counted RELATIVE to the last prompt's start (same as `cancel_after_updates`, `recorder.rs:228-238`), so the steer cannot race the prompt's streamed updates (`session/new` itself emits an `available_commands_update`, `recorder.rs:31-36`, so absolute counts are wrong); corpus uses `after_updates: 2` = both step-2 text deltas drained
9. Step 3 of each transcript starts with `{"sleep_ms":100}` (`fake-claude/src/lib.rs:340`) so the `_session/steering` response (Node replies after `await publishGoalFromPrompt`, `dist:1181`; Rust via spawned responder, `agent.rs:~752`) cannot interleave with step-3 updates (frame diff is order-sensitive, `differential.rs:23-45`)
10. Node fixtures are generated by `porting/capture.sh <name>` and committed; Rust is diffed against them via `run_and_diff` (`differential.rs:323`)
11. Phase 1 implementation deviation: the R8 echo-hand-off branch guard in `on_echo` is written `else if let Some(steered) = prev.steered_settle` rather than the literal `else if is_steering_turn(&prev) && prev.steered_settle.is_some()` to satisfy `clippy -D warnings` (avoids `unwrap` on the `Option`). Semantically equivalent: `steered_settle` is `Some` only while the turn is steering — `mark_steered` sets `steered_echoes` and moves `deferred_settle` into `steered_settle`, and the steer idle lane moves it back to `deferred_settle` and clears both. It still sits after the cancelled and held (`deferred_settle`) branches and before the end_turn fallback, exactly as specified
12. Phase 2 Opus-review follow-up: `steer_echo_handoff_uses_steered_settle` previously recorded the steered result with `stop_reason:"end_turn"` and usage equal to the accumulated total, so its stop_reason/usage asserts could not distinguish the R8 branch from the end_turn fallback. The steered result now uses `stop_reason:"max_tokens"` with a distinct usage `{input_tokens:2, output_tokens:4}`; the assert now expects `StopReason::MaxTokens` and that usage — the fallback would settle `EndTurn`, so the R8 branch is provably exercised. All other tests unchanged
13. Phase 3 implementation note (3.8): the INVARIANTS.md Evidence block was refreshed from the real `-p claude-agent-acp-rs` test output (lib 79 -> 93, differential 17 -> 22); the previously-grouped "3 passed (control_transport, transport_parity, shutdown, recorder)" line was expanded to per-binary real counts (control_transport 1, shutdown 3, transport_parity 1) since the group was stale vs the measured output. No implementation deviation; the corpus/fixture contracts and differential tests match the plan literally.
